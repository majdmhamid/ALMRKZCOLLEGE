# تشغيل نظام التوقيع الإلكتروني — خطوة بخطوة

<div dir="rtl">

## الفكرة باختصار

النظام إله 3 أجزاء:

| الجزء | شو هو | وين |
|---|---|---|
| **التطبيق** | الصفحات اللي بتشوفها أنت والعملاء | Vercel (استضافة مجانية) |
| **قاعدة البيانات والملفات** | المستندات، التوقيعات، الروابط | Supabase (مجاني للبداية) |
| **الكود** | كل إشي مكتوب | GitHub، بمجلد `signing` |

كل خطوة تحت بتاخد دقايق. **إذا علقت بأي خطوة، احكي لكلود بالعربي شو شايف قدامك وهو بكمّل معك.**

---

## ١. اعمل مشروع على Supabase

1. ادخل على **https://supabase.com** واعمل حساب (بتقدر تدخل بحساب GitHub).
2. اضغط **New project**.
3. عبّي:
   - **Name:** مثلاً `almrkz-signing`
   - **Database Password:** اضغط **Generate a password** و**احفظها بمكان آمن** (رح نحتاجها بالخطوة ٣).
   - **Region:** اختار **Central EU (Frankfurt)** — الأقرب لإلنا.
4. اضغط **Create new project** واستنى دقيقتين لحد ما يجهز.

### سكّر التسجيل العام (مهم جداً)

ما بدنا حدا غريب يعمل حساب لحاله:

1. من القائمة: **Authentication** ← **Sign In / Providers**
2. طفّي **Allow new users to sign up**
3. اضغط **Save**

---

## ٢. جهّز الملف السرّي `.env.local`

هاد ملف فيه المفاتيح. **بضل على كمبيوترك بس، وما بنرفع على GitHub.**

1. افتح مجلد `signing` بالتيرمينال، أو احكي لكلود: *"افتح مجلد signing"*.
2. شغّل:

```bash
npm install
```

```bash
npm run secrets
```

هيك انعمل ملف `.env.local` فيه 3 مفاتيح سرّية جاهزة.

3. افتح `.env.local` وعبّي هدول من Supabase:

| بالملف | من وين بتجيبه بـ Supabase |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | **Project Settings** ← **Data API** ← **Project URL** |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | **Project Settings** ← **API Keys** ← المفتاح اللي اسمه **anon** أو **publishable** |
| `SUPABASE_SERVICE_ROLE_KEY` | نفس الصفحة ← **service_role** أو **secret** (اضغط Reveal) |
| `SUPABASE_DB_URL` | زر **Connect** فوق ← **Session pooler** ← انسخ الرابط، وحط كلمة سر قاعدة البيانات (من الخطوة ١) مكان `[YOUR-PASSWORD]` |

> ⚠️ **مفتاح `service_role` زي مفتاح الخزنة.** لا تبعته لحدا، ولا تحطه بواتساب أو إيميل.

---

## ٣. ابني قاعدة البيانات

```bash
npm run db:migrate
```

لازم تشوف ✓ جنب كل ملف. هاد بيعمل كل الجداول، وبيسكّر الوصول على الكل غير المدير، وبيعمل 3 خزائن ملفات خاصة (مش عامة).

بعد كل تحديث للنظام بالمستقبل بتشغّل نفس الأمر، وهو بيضيف بس الجديد.

---

## ٤. اعمل حساب المدير (أنت)

```bash
npm run admin:create
```

رح يسألك 3 أسئلة: البريد، الاسم اللي بيطلع بالنظام، وكلمة سر (12 حرف أو أكثر).

بدك مدير ثاني؟ شغّل نفس الأمر مرة ثانية.

---

## ٥. جرّب على كمبيوترك

```bash
npm run dev
```

افتح **http://localhost:3100** وادخل بالبريد وكلمة السر من الخطوة ٤.

---

## ٦. انشر على الإنترنت (Vercel)

1. ادخل على **https://vercel.com** واعمل حساب بحساب GitHub.
2. **Add New** ← **Project** ← اختار `ALMRKZCOLLEGE`.
3. **مهم:** بـ **Root Directory** اضغط **Edit** واختار `signing`.
4. افتح **Environment Variables** وضيف كل سطر من `.env.local` **ما عدا** `SUPABASE_DB_URL` وأسطر الـ `MOCK`.
   - `NEXT_PUBLIC_APP_URL`: حط مؤقتاً أي إشي، وبعد النشر غيّره للعنوان اللي أعطاك إياه Vercel (مثلاً `https://almrkz-signing.vercel.app`) واعمل **Redeploy**.
5. اضغط **Deploy**.

بعد النشر، ارجع على Supabase: **Authentication** ← **URL Configuration** ← **Site URL** = عنوان Vercel.

> 💡 بدك عنوان زي `sign.almrkz.net`؟ بـ Vercel: **Settings** ← **Domains**. بعدها غيّر `NEXT_PUBLIC_APP_URL` لنفس العنوان.

## أشياء لازم تعرفها

| الموضوع | الشرح |
|---|---|
| **لا تغيّر المفاتيح السرّية** | `ID_HMAC_SECRET`، `TOKEN_ENC_KEY`، `SESSION_SECRET` — لو تغيّروا بعد ما بلّشت، أرقام الهويات المحفوظة ما بتتطابق والروابط القديمة ما بتنسخ. خلّي نسخة منهم بمكان آمن. |
| **Supabase المجاني بينام** | إذا ما حدا استعمل النظام 7 أيام، المشروع بيتوقف. بترجع بتشغّله من لوحة Supabase بكبسة (**Restore**). لما يصير الشغل يومي، مش رح تحس فيها. |
| **المساحة** | المجاني فيه 1 جيجا للملفات. الرقم بيطلع على بطاقة "المساحة" بصفحة المستندات. |
| **النسخ الاحتياطي** | المجاني ما فيه نسخ تلقائي طويل. لما يصير النظام أساسي بالشغل، بنرجع نحكي عن الخطة المدفوعة. |

## وضع التجربة (للتطوير بس)

بدك تشوف الشاشات بدون Supabase؟

```bash
npm run dev:mock
```

بيشتغل ببيانات وهمية على كمبيوترك. البريد وكلمة السر للتجربة موجودين بملف `.env.example` (سطور `MOCK_ADMIN_...`).
